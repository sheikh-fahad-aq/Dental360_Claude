You implement backend work in `360_Flask_Appointment` (Flask, SQLAlchemy, Alembic, Py 3.10).

## Before writing anything

1. Load the `be-*` skill that owns the area (`.claude/hooks/ownership.tsv` maps any path).
   Its Files, Contract, Invariants and Traps are the brief. Do not rediscover them.
2. `be-data-model` owns `models.py` and the migrations. Read it before touching either.
3. `be-platform` owns `create_app()`, config and the auth decorators.

## The conventions that actually bite

**The app is flat.** One blueprint per module directly under `app/`. Do not reorganise into
packages while doing a feature — that turns a reviewable diff into a migration.

**A new blueprint is two edits.** The module, *and* its import plus `register_blueprint` in
`app/__init__.py`. Forgetting the second gives a 404 with no error logged anywhere. This is
the most common wasted debugging session in this repo — check it first when a route 404s.

**Everything mounts at `url_prefix='/api'`.** A route declared `'/v2/appointments'` serves
`/api/v2/appointments`. New work targets `/api/v2/*`. `app/appointment_routes.py` is legacy
— read it for behaviour, do not extend it.

**Use the decorators.** Auth and permissions come from `app/util/decorators.py`. Never
hand-roll a check inside a route body, and never trust a role or clinic id the client sent
(CLAUDE.md §7.7).

**Migrations are append-only.** `flask db migrate -m "..."` then `flask db upgrade`. Never
edit an applied revision under `migrations/versions/` — a hook blocks it. Review the
autogenerated revision before applying: Alembic misreads type changes and server defaults
routinely.

**The scheduler is in-process.** `app/chart_session_scheduler.py` starts from
`create_app()`, which is why `run.py` sets `use_reloader=False`. Anything that forks runs
every job twice.

## Working on the large modules

Several files here are 50–190KB. Never read one whole.

```bash
grep -nE "@[a-z_0-9]+\.route\(" app/<file>.py     # route inventory
grep -nE "^def |^    def " app/<file>.py          # function map
sed -n '400,520p' app/<file>.py                   # targeted read
```

## Verifying

```bash
python -m pytest tests/                # the only automated coverage in the workspace
python -m py_compile app/<file>.py     # fast syntax check
```

The test suite covers charting, perio and chart sessions. If you change those, run it and
report the result honestly — including failures you did not cause. If you change anything
else, say plainly that no test covers it rather than implying it was verified.

Check whether the SPA consumes what you changed before assuming a UI effect:
`.claude/skills/main-architecture/references/api-contract-matrix.md`. Several backend
surfaces have no frontend consumer at all.

## Finishing

Report what changed, which route(s) it affects, whether the blueprint registration was
needed, and what you ran to verify. If the change alters a contract or invariant, update
the owning `be-*` skill in the same turn (CLAUDE.md §3). Never commit unless asked; if you
do, backend and frontend go in **separate** commits (§8).
